# คู่มือครู Week 01 — รู้จักระบบปฏิบัติการหุ่นยนต์และความปลอดภัย

**เวลา:** 100 นาทีต่อเนื่อง  
**บทนักเรียนที่ใช้คู่กัน:** `docs/education/weeks/week-01.md`

## 1. ความรู้ที่ครูควรทบทวนก่อนสอน
ครูควรเข้าใจความแตกต่างของคอมพิวเตอร์ระดับสูงกับไมโครคอนโทรลเลอร์ก่อนอธิบายให้นักเรียนฟัง

- **Raspberry Pi 4** เป็นคอมพิวเตอร์ที่รัน Ubuntu และ ROS 2 เหมาะกับงานระดับสูง เช่น ROS graph, controller, logging และ application
- **ESP32** เป็น microcontroller เหมาะกับงานควบคุมเวลาแน่นกว่า เช่น PWM, อ่าน encoder และ watchdog
- **Motor Driver** ไม่ได้ “คิด” แทน ESP32 แต่ทำหน้าที่รับสัญญาณควบคุมและจ่ายกำลังให้มอเตอร์
- **Encoder** เป็น sensor ที่ให้ feedback การหมุนของเพลา
- **ROS 2** เป็น middleware/framework สำหรับให้โปรแกรมหลายส่วนสื่อสารกันเป็นระบบ

ครูควรใช้คำว่า “ระบบหุ่นยนต์” ในความหมายของการรวม Compute + Embedded + Actuator + Sensor + Communication + Software ไม่ใช่หมายถึงตัวถังเพียงอย่างเดียว

## 2. แนวคิดที่ต้องทำให้นักเรียนเข้าใจ
### Compute กับ Control ต่างกันอย่างไร
เปรียบเทียบง่าย ๆ: Raspberry Pi เหมือน “สมองที่วางแผนและสื่อสาร” ส่วน ESP32 เหมือน “ไขสันหลัง/ระบบควบคุมระดับล่าง” ที่รับคำสั่งและตอบสนองกับมอเตอร์/encoder โดยตรง

อย่าอธิบายว่า Pi “ฉลาดกว่า” ESP32 อย่างเดียว เพราะจะทำให้นักเรียนคิดว่า ESP32 ไม่มีความสำคัญ ให้เน้นว่าแต่ละอุปกรณ์ถูกออกแบบให้เหมาะกับหน้าที่ต่างกัน

### Open-loop กับ Closed-loop
ถ้าสั่ง PWM แล้วไม่วัดผล ถือว่าเป็น open-loop. เมื่อใช้ Encoder วัดการหมุนและนำกลับไปปรับคำสั่ง ถือว่าเป็น feedback/closed-loop control

### Differential Drive
หุ่นมีล้อขับ 2 ล้อ ซ้าย–ขวาอยู่กลางฐาน และมี caster ball หน้า/หลังสำหรับประคองตัว
- ล้อซ้าย=ล้อขับ
- ล้อขวา=ล้อขับ
- caster ไม่ใช่ drive joint

ถ้าล้อซ้ายและขวาหมุนเท่ากันในทิศเดียวกัน หุ่นมีแนวโน้มเคลื่อนตรง
ถ้าความเร็วต่างกัน หุ่นเลี้ยว
ถ้าหมุนสวนกัน หุ่นสามารถหมุนอยู่กับที่ได้

## 5. ลำดับสอน 100 นาทีอย่างละเอียด
### นาที 0–10 — Engage
แสดงหุ่นโดยไม่อธิบายก่อน แล้วถาม:
> “ถ้าเราต้องการให้คำสั่งจาก Ubuntu ทำให้ล้อหมุนได้ ข้อมูลต้องผ่านอะไรบ้าง?”

อย่าเฉลยทันที ให้เด็กชี้อุปกรณ์และเดาเส้นทางก่อน

คำตอบที่ครูควรค่อย ๆ พาไป:
`ROS 2 / Raspberry Pi → UART → ESP32 → PWM/DIR → Motor Driver → Motor`

### นาที 10–40 — Explore
ให้แต่ละกลุ่มจับอุปกรณ์หรือดูหุ่นจริงและกรอกตาราง หน้าที่/ข้อมูลเข้า/ข้อมูลออก

ครูเดินตรวจและใช้คำถามแทนการเฉลย เช่น:
- “ตัวไหนต่อกับ Linux?”
- “ตัวไหนรับสัญญาณ encoder?”
- “Motor Driver รู้ตำแหน่งล้อเองหรือไม่?”
- “Encoder สั่งมอเตอร์หรือวัดมอเตอร์?”

### นาที 40–60 — Explain
วาด Command Flow และ Feedback Flow แยกสีบนกระดาน

อธิบายว่า “คำสั่ง” กับ “ข้อมูลวัดกลับ” เป็นคนละทิศทาง

Command:
`ROS 2 → Pi → ESP32 → Driver → Motor`

Feedback:
`Encoder → ESP32 → Pi → ROS 2 → Odometry/Diagnostics`

จากนั้นอธิบาย Differential Drive ด้วยการหมุนล้อด้วยมือ ไม่ต้องจ่ายไฟ

### นาที 60–85 — Elaborate
ให้แต่ละกลุ่มวาด System Architecture ของตนเอง ต้องมีอย่างน้อย 6 block:
ROS 2, Raspberry Pi, UART, ESP32, Motor Driver, Motor/Encoder

ครูตรวจว่ามีลูกศร feedback กลับด้วย ไม่ใช่มีแต่คำสั่งไปทางเดียว

### นาที 85–100 — Evaluate
ตรวจ 3 อย่าง:
1. แผนภาพระบบ
2. Safety Checklist
3. Exit Ticket

## 6. จุดที่นักเรียนมักสับสน
### “ROS 2 อยู่ใน ESP32 ใช่ไหม?”
ตอบ: ในโครงการนี้ ROS 2 หลักรันบน Raspberry Pi ส่วน ESP32 ใช้ firmware สำหรับควบคุมระดับล่างและสื่อสารกับ ROS 2 ผ่าน UART

### “Motor Driver คือ microcontroller ใช่ไหม?”
ตอบ: ไม่ใช่ ในบริบทนี้ MDD10A เป็นวงจรขับกำลัง ไม่ได้รัน ROS node หรือ firmware ควบคุมหลัก

### “Encoder ทำให้มอเตอร์หมุน?”
ตอบ: Encoder เป็นตัววัดการหมุน ไม่ใช่ตัวขับมอเตอร์

### “Caster Ball ต้องอยู่ใน diff-drive controller ไหม?”
ตอบ: ไม่ใช่ drive wheel จึงไม่ใช้คำนวณคำสั่งล้อของ differential drive

## 7. คำถามชี้นำพร้อมคำตอบที่คาดหวัง
**ถาม:** ทำไมไม่ต่อมอเตอร์เข้ากับ ESP32 โดยตรง?  
**คาดหวัง:** ESP32 ให้สัญญาณควบคุม ไม่ได้ถูกออกแบบให้จ่ายกระแสกำลังของมอเตอร์ จึงต้องใช้ Motor Driver

**ถาม:** ถ้าไม่มี Encoder เรารู้ว่าล้อหมุนจริงหรือไม่?  
**คาดหวัง:** รู้ได้ยาก/ไม่ทราบจำนวนรอบและทิศอย่างน่าเชื่อถือ จึงต้องมี feedback

## 8. การสาธิตที่แนะนำ
หมุนล้อซ้ายด้วยมือและถามว่า “sensor ไหนรับรู้?” จากนั้นชี้ Encoder → ESP32 → ROS 2 เพื่อทำให้ feedback concept เป็นรูปธรรม

## 9. Safety Notes สำหรับครู
